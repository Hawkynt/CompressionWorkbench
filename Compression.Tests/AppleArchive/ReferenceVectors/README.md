# Apple Archive reference vectors

## Written by Apple's `aa`

`aa-*.aar` were written by `aa archive` on macOS 26.6.2 (build 25G83), on a GitHub Actions
`macos-latest` runner. The workflow `.github/workflows/oracle-apple-archive.yml` exists only on the
utility branch `oracle/apple-archive`. The input tree:

| Item | Content | SHA-256 |
| --- | --- | --- |
| `notes.txt` | 700 generated text lines (27 827 bytes) | `0e1a649b…f6880b` |
| `sub/data.bin` | 12 000 generated bytes | `435a256d…4480d7` |
| `sub/noise.bin` | 20 000 random bytes | `70492565…ca0d6f` |
| `empty.txt` | empty | |
| `link-to-notes` | symlink to `notes.txt` | |

Full hashes are in `AppleArchiveTests`. Every file is timestamped 2024-05-06 07:08:10 UTC.

| File | Command | Container |
| --- | --- | --- |
| `aa-raw.aar` | `aa archive -a raw` | plain AA01 items |
| `aa-lzfse.aar`, `aa-zlib.aar`, `aa-lzma.aar`, `aa-lz4.aar`, `aa-lzbitmap.aar` | `-a lzfse` / `zlib` / `lzma` / `lz4` / `lzbitmap` | pbze / pbzz / pbzx / pbz4 / pbzb, one 4 MiB block |
| `aa-lzfse-16k.aar`, `aa-zlib-16k.aar` | `-b 16k` | 16 KiB blocks; the noise blocks are stored uncompressed |

`aa-listing.txt` is `aa list -v` for each archive.

## Ours, checked by `aa`

The same workflow runs `aa list -v` and `aa extract` on archives our writer produced: raw, LZFSE
and zlib, plus an edit of `aa-zlib.aar` that adds one file and removes another. The results are in
`aa-ours-listing.txt`.
