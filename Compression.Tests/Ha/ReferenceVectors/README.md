# HA reference vectors

The reference program is `ha.exe` from <https://github.com/val-khokhlov/ha> release `v0.999b`, a
Win32 build of HA 0.999 beta at revision f112fbeb282c2393639393f759a11887c0dad3b5.

## Archives

| File | Command | Exercises |
| --- | --- | --- |
| `hsc.ha` | `ha a2rdq hsc.ha in\*.*` | HSC, with context recycling, node release and the drop to order 3; a directory record; CPY fallback for the 1-byte file |
| `asc.ha` | `ha a1rdq asc.ha in\*.*` | ASC: long matches, distances across the whole window, every distance class |
| `cpy.ha` | `ha a0q cpy.ha in\tiny.txt in\empty.txt` | stored members |
| `ours.ha` | our `HaWriter` (see `WriteProbe.Ha`) | `ha t` and `ha x` accept it; see below |

`HaReferenceTests` asserts the listings `ha lf` printed. It also checks that every member extracts
to the input bytes (the reader verifies each CRC-32), and that `HaHsc.Encode` reproduces both HSC
streams in `hsc.ha` byte for byte.

## Our writer, checked by the oracle

`ours.ha` holds:
- a `docs` directory record
- `docs/text.txt` (HSC)
- `raw.bin` (HSC)
- `empty.txt` and `tiny.txt` (CPY, because HSC does not shrink them)

`ha lf ours.ha` lists all five, `ha t ours.ha` tests every member, and `ha xy` writes files whose
SHA-256 match the inputs (`ha-listing-ours.txt`). The file is pinned byte for byte.

An edit was also checked. `HaModifier` removed `in/tiny.txt` from a copy of `hsc.ha`, replaced
`in/empty.txt` and added `added/new.txt`. `ha t` and `ha xy` accept the result, and the untouched
members extract to the original SHA-256 values. The edit was not committed; the byte-for-byte copy
of untouched records is asserted in `HaTests`.

## The original 1995 archive

`HA_SRC.HA` (archive.org item `ha-0.999beta`, md5 32bc5e964219c3fc00bef392efc2fb77) was written
by the original DOS `ha.exe`, which the author built partly from hand-optimised assembly. It holds
35 members (34 HSC, one ASC), and every one decodes with a matching CRC-32. Because its members are GPL source
files, it is not committed here.
